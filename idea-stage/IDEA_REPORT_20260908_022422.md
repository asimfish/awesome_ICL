## 一页结论

1. **可以做、且值得做的不是「更小的 HOST」，而是对 HOST 这一类主张的机制审计、信息边界测量与记忆内容鉴别。** 三个模型（生成 ×2、评审 ×1）与外审独立收敛到同一判断：在冻结的开放权重上做受控反事实实验，比用小数据复刻预训练更有信息量，也更能发到 CoRL/RSS。
2. **首选 C01「同一终点、两种程序」**：在 RLBench 上构造初始观测相同、最终状态相同、但正确交互顺序不同的成对任务，用 Instant Policy 冻结权重做 one-shot 推理，以接触事件序列判定模型读到的是**程序**还是**目标/任务标签**。陪审排名第 1，外审评分 8/10，查新 5.5/10 PROCEED WITH CAUTION（须与 TTP、StellaVLA 三向干预明确区分）。外审给出的论文题：*Does One-Shot Robot Imitation Follow the Demonstrated Procedure? A Terminal-State-Controlled Audit of In-Context Policies*。
3. **次选 C07「视觉演示的接触参数可辨识性边界」**：在 robosuite Door/Wipe 构造视觉孪生的物理参数对，穷举预注册执行原语，测「共同安全成功动作集合」是否为空。单卡四天、不需要任何大模型；查新 7/10 PROCEED，外审 7/10。把「纯视觉必然缺力」从被反复引用的假设变成可测量的边界。
4. **高上行名额 C18「记忆移植」**：在 Zeva 公开 PIM 上做任务身份 × 动力学的析因供体历史移植，只看接收端首次尝试，鉴别 Zeva 式「学自己」学到的是物理知识、任务标签还是成功轨迹重放。查新 5/10 CAUTION（Zeva 是压倒性近邻），外审 6.5/10，**先过加载与 positive-control 门，不过即降为替补**。
5. **第一替补 C20「演示选择偏差记账」**：量化「最终只放一条演示 ≠ 只用过一条」的隐性优势，解释链条最短、预算最清楚。
6. 三条主线分别检验**过程依赖、观测充分性、记忆内容**，失败原因分散在不同系统与假设上——这是陪审有意为之的组合，而非按分数机械取前三。

## Robotics Problem Frame（Phase 0 摘要，全文见 `ROBOTICS_FRAME_AND_LANDSCAPE.md`）

- **具身**：桌面操作臂，单臂 / 双臂平行夹爪（HOST 权重绑定双 ARX R5）；无灵巧手
- **任务族**：短程桌面操作为主，长程组合为次
- **观测 / 动作接口**：多路 RGB + 本体 + 语言；末端位姿增量或关节块（16–32 步）
- **可用资产**：开放权重 HOST / Fast-WAM / EgoWAM / DreamZero / LingBot-VA v1 / Zeva / ICRT / RICL / Instant Policy / StellaVLA / RoboMonkey 验证器 / π0.5 / Wall-OSS / SmolVLA / OFT；开放数据 ICRT-MT / DROID / LIBERO / RoboTwin 2.0 / RoboCasa365 / RLBench / AgiBot World；本仓库口径账本与 22 条机会清单
- **约束**：≤ 8×80GB × ≤ 1 周；sim-first，真机需显式批准；不做规模复现
- **期望贡献**：诊断 / 评测协议 / 推理期或小数据方法 / 小规模数据

## Ranked Ideas

### Idea 1：C01 · 同一终点、两种程序：演示传递的是过程还是任务标签 — RECOMMENDED

- **具身**：仿真 Franka 单臂 + 平行夹爪
- **基准 / 仿真器**：RLBench（CoppeliaSim）；自建 4 对「同初态、同终态、异程序」两步任务，每对 20 布局，两个程序方向都跑；模型为 Instant Policy 官方冻结权重（`num_demos=1`，无重试）
- **所针对瓶颈**：缺口 4（读演示 vs 捷径）、缺口 6（口径）
- **Pilot 类型**：仿真；2×80GB × 5 天，800 次主 rollout + 单步原语能力门
- **五条件**：正确程序 / 相反但合法程序 / 仅终态图像 / 无演示 / 外观变化但程序相同
- **正面信号**：单步原语 ≥ 80%、两步脚本可达性 ≥ 95% 前提下，换程序演示时**首次分叉选择与完整顺序一起切换**，且换外观不产生同量级变化
- **可发表的负结果**：能力门通过但模型稳定只追终态或任务捷径——界定现有 one-shot 主张的机制边界
- **查新**：5.5/10，PROCEED WITH CAUTION。最近邻：Transformers are Adaptable Task Planners（高层规划中的「同终态异顺序偏好」）、StellaVLA 三向干预、ICRT 捷径分析、Instant Policy 自身消融；BPP 为 2026 并行工作。可辩护 delta：**在低层冻结 ICIL 权重上，用同初态/同终态/相反合法程序的成对反事实与接触事件级判定，把「读程序」与「读目标/标签」分开**——本次检索未见任何已发表工作包含该结果
- **外审评分**：8/10。致命风险：原语能力地板不过、两步间中间状态不可观察、「同终态」实际不成立、隐式任务 ID 泄漏、只用终态成功率作结论。可管理风险：单模型、纯仿真、任务少——靠窄化标题管住（写 terminal-state-controlled audit，不写 program understanding）
- **真机**：不必需；仅「人类真实演示是否同样传递程序」「真实相机分割/遮挡下是否成立」两类 claim 需要
- **下一步**：先做原语能力门与两步可达性检查（1–2 天），再搭接触事件判定器与程序级 judge，最后跑 800 次主实验

### Idea 2：C07 · 视觉演示的接触参数可辨识性边界

- **具身**：仿真 Panda 单臂；执行侧仅 RGB + 本体
- **基准 / 仿真器**：robosuite Door 与 Wipe（MuJoCo）；每任务 100 对视觉孪生实例（铰链阻力 / 摩擦 / 接触刚度不同、接触前 RGB+本体历史经判别器核验不可区分）
- **所针对瓶颈**：缺口 9（力信息）、缺口 6
- **Pilot 类型**：仿真分析型；1×80GB × 4 天，≤ 2,000 次短 rollout；不需要大模型
- **对照**：5 个预注册速度/阻抗原语网格、固定保守原语、随机原语、参数已知 oracle 上界
- **正面信号**：一段参数区间内同时出现「决策前不可区分 + 共同安全成功动作集合为空 + oracle 可成功」
- **可发表的负结果**：共同稳健动作普遍存在 → 推翻该任务族「缺力信息必然失败」的解释
- **查新**：7/10，PROCEED。近邻 ForceMimic / VISTA / FACTR 2（证明力有用）、Belief-Grounded Networks / RMA（POMDP 与隐参数适应）、Push to Know / Active Sensing Motor Policies（主动感知）；delta 是**反向给出「力 / 试探何时必要」的可核验边界**，而非再证明「力有用」
- **外审评分**：7/10。致命风险：人为制造不可解（原语过窄、阈值为结论服务）、视觉孪生只匹配首帧、oracle 也不成功、空集只出现在单个反例。必做阈值与原语集合敏感性；接触后可分性须单独报告，结论只针对「首次关键接触决策前」
- **真机**：不必需
- **下一步**：预注册参数轴、原语库与安全阈值（写入仓库后再跑），先做 Door 单轴

### Idea 3：C18 · 记忆移植：自我改进包含可迁移的物理知识吗 — 高上行、带启动门

- **具身**：RoboCasa PandaOmron
- **基准 / 仿真器**：RoboCasa365 Atomic5 铰链任务（OpenStandMixerHead、CloseToasterOvenDoor）× 两档铰链阻尼；Zeva 官方实现 + `chen123fu/zeva-robocasa` PIM 适配器
- **所针对瓶颈**：缺口 2、4、6（学自己的记忆内容）
- **Pilot 类型**：仿真；≤ 8×80GB × 6 天，320 次接收 rollout（区间过宽扩到 640）
- **设计**：接收端只允许一次尝试；四组供体历史——同动力学异任务 / 同任务异动力学 / 等长度打乱 / 空；外审强制加「同任务同动力学」positive-control（不进主 claim）；success replay 关、BIT 每次清空
- **正面信号**：同动力学异任务 > 同任务异动力学 > 打乱 ≈ 空，两任务方向一致
- **可发表的负结果**：positive-control、阶段匹配、动作支持、注入有效性均通过后，收益仍只随任务身份或成功轨迹移动
- **查新**：5/10，PROCEED WITH CAUTION。Zeva 是压倒性近邻（含 cross-task causal signal transfer）；delta 是**任务身份 × 动力学的析因移植 + 首次尝试读出**。若 Zeva 正文/附录已有同等 donor ablation，应立即降为 1–3 分
- **外审评分**：6.5/10。致命风险：PIM 链路无法复现、positive-control 无效、success replay 泄漏、跨任务阶段表示不对齐。**启动门不过直接砍，不加适配模块救**
- **真机**：否
- **下一步**：第一天核对基座 SHA / 适配器 / PIM 注入 / 空记忆重复性；门过后再采供体

### 第一替补：C20 · 演示选择偏差记账

Instant Policy `deploy_sim.py` + RLBench 4 任务；每任务 8 条演示、10 选择布局、20 隐藏测试布局；比较随机一条 / 只看演示选择 / 允许试跑后选一条；960 次 rollout，2×80GB × 5 天。前三任一在启动检查阶段失效即由它接替。

## Evidence Package for the Top Idea（C01，来自外审）

- **必需基线 / 条件**：正确程序、相反合法程序、仅终态、无演示、外观变化；单步原语 positive-control（≥ 80%）与两步脚本可达性（≥ 95%）
- **必需指标**：终态成功率与完整程序成功率分列；首次分叉正确切换率（核心量）；顺序颠倒、重复、漏步、碰撞、超时；按任务对与布局配对的置信区间
- **必需失败分析**：首步错但终态成功计为程序失败；终态图像条件接近正确演示 → 任务太易；外观变化造成同量级差异 → 测到的是视觉分布偏移
- **必需审计**：程序 judge 泄漏审计——任务名、语言、成功函数、对象 ID、演示文件名不得把顺序送进策略
- **真机是否必需**：否。若要声称「robot ICIL 普遍问题」需第二个接口族（如 StellaVLA 或 ICRT），否则定位为 Instant Policy 机制审计
- **核心图**：三栏——左：同初态同终态的两种合法程序演示；中：五条件下首次分叉选择的混淆矩阵；右：终态成功率与完整程序成功率分离的配对置信区间
