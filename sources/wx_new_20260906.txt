1. 开篇：为什么异步执行下的在线 RL 突然变得重要？
想象一个场景：你把一个参数量数十亿的 VLA 模型部署到真实机器人上，让它完成一个抛掷任务——抓起桌上的物体，挥臂，在精确的时刻松手，让物体落入远处的容器。模型推理一次需要 100–300 毫秒。如果采用同步执行，机器人必须在每个action chunk的边界停下来，等下一次前向传播完成，再继续运动。在抛掷这种需要持续加速的高动态任务里，这一停顿足以让手臂速度归零，后续的挥臂再也无法恢复到所需的释放速度——任务直接失败。
这不是假设。随着VLA和WAM规模持续膨胀，推理延迟已经成为部署侧的硬约束。现代机器人系统的标准做法是动作分块 + 异步推理：策略在后台推理下一个分块的同时，机器人继续执行当前分块，推理完成后立即切换。这样延迟被"隐藏"了，控制频率不再受限于推理速度。
但异步执行引入了一个新问题：每个新分块是基于一个过时的观测生成的，它不知道从上一帧观测到现在机器人已经执行了什么动作。于是在分块交接的边界，速度或加速度可能出现跳变。为了解决这个问题，社区发展出了两类平滑手段：前缀一致性约束（chunk stitching）和轨迹混合（trajectory blending）。
与此同时，另一条线的研究在追求可靠性：预训练的 VLA 策略在真实部署中往往存在系统性偏差（比如总是偏左几毫米），需要在线 RL 来微调。RLT、EXPO-FT 等工作证明了在冻结的 VLA 上加一个轻量残差模块、用值梯度在线更新，可以在几十到几百个 episode 内显著提升成功率。
问题在于，这两条线几乎是独立发展的。现有在线 RL 方法几乎都假设同步执行——它们在一套动力学下优化策略，却在另一套（异步）动力学下部署。训练时认为"策略输出的整个分块都会被执行"，部署时实际上只有一部分被执行，其余被下一个分块覆盖。这种训练-部署不匹配，会让值梯度回传到那些从未进入环境的动作上，造成"梯度污染"。
SmoothRL（Astribot Team, 2026）的核心主张可以用一句话概括：在部署用的异步循环里直接做值梯度在线微调，而不是先同步训练再异步部署。 论文提出了一个干净的形式化方案——将每个动作分块按帧索引划分为三个区域，只对真正被执行的区域回传值梯度，同时在训练时就运行异步推理循环，确保回放缓冲区记录的是机器人真正执行的动作。

2. 背景速览：从 VLA/WAM 到Action Chunking与异步推理
2.1 VLA 与 WAM 的规模-延迟矛盾
以 ₀、₀.₅、GR00T N1、RDT-1B 为代表的 VLA 模型，以及 Cosmos Policy、Fast-WAM 等 WAM，展示了令人印象深刻的泛化能力。但规模的代价是推理延迟：一次完整的前向传播通常需要数十到数百毫秒。如果控制频率要求 30 Hz（每帧约 33 ms），同步推理根本无法满足实时性要求。
WAM 引入了世界模型的想象能力，理论上可以通过多步预测来规划动作，但这进一步增加了计算量。规模-延迟矛盾是当前机器人基础模型部署的核心工程张力之一。
2.2 Action Chunking为何成为标准
Action Chunking的思路很直接：策略一次推理输出  帧的动作序列，而不是单帧动作。这样即使推理需要 200 ms，只要  足够大（比如 

，30 Hz 下约 1 秒），机器人就有足够的动作可以执行，推理与执行可以重叠。Diffusion Policy、ACT 等工作确立了这一范式，如今已成为大模型机器人策略的标准部署方式。

但分块本身不解决延迟问题——它只是提供了"可以被异步执行的素材"。真正隐藏延迟的是异步推理。
2.3 同步 vs 异步执行的本质区别
同步执行：机器人执行完当前分块后，停下来等待下一次推理完成，再执行新分块。控制频率等于推理频率。优点是每个分块都是基于最新观测生成的，策略输出等于机器人执行；缺点是边界停顿，高动态任务直接失败。
异步执行：推理与执行重叠。机器人执行当前分块的同时，后台在推理下一个分块。新分块一旦就绪，立即接管执行。控制频率不受推理延迟限制。但代价是：新分块是基于一个过时的观测生成的（推理开始时的观测），它不知道在推理期间机器人执行了什么。因此在分块交接处，新分块的第一帧动作可能与当前正在执行的动作不连续，产生速度或加速度跳变。
2.4 现有平滑手段简评
针对异步执行的边界不连续问题，主要有两类方法：
前缀一致性约束（Chunk Stitching）：要求新生成的分块的前若干帧（已经被前一个分块"消耗"的部分）与已经执行的动作匹配，其余部分自由生成。代表工作包括 Real-Time Execution of Action Chunking Flow Policies、TT-RTC（Training-Time Action Conditioning）等。这类方法从推理时的外部引导逐步演进到训练时的策略内部建模，从硬前缀约束演进到软插值。
轨迹混合（Trajectory Blending）：不对策略输出本身做约束，而是在多个分块生成后，用衰减插值权重对重叠部分做后处理平滑。代表工作如 Low-Cost Hardware 中的 ALoha 方案。
这两类方法对模仿学习和离线 RL 来说区别不大——因为它们不涉及值梯度回传。但对在线 RL 来说，这个区别是决定性的：在线 RL 要求  函数评估的动作必须恰好是机器人执行的动作（agreement），同时这个动作必须有一条可微路径回到策略参数（differentiability）。前缀约束在策略输出前就固定了动作，天然满足 agreement；而混合操作在多个分块都生成后才决定执行动作， 评估的对象变得复杂。
2.5 过渡：现有在线 RL 的同步假设
现有在线 RL 方法——无论是 RLT 的 RL Token、EXPO-FT 的残差编辑头，还是 RL、ReinFlow 等端到端微调——都假设同步的 receding-horizon 执行。在它们的公式里，策略生成的整个分块都会被执行，值梯度可以回传到分块的每一帧。但在异步部署中，每个分块只有一部分被执行，其余被下一个分块覆盖。这意味着：优化在一套动力学，部署在另一套动力学。SmoothRL 的目标就是消除这个不匹配。
3. 问题形式化：异步在线 RL 的三条硬要求
论文在引言中提出了一个简洁的分类框架，用三条要求来定位现有工作的位置：
Online：策略从当前正在生成的数据中学习，而不是通过离线训练轮次。

Asynchronous：推理与执行重叠，模型推理延迟不限制控制频率。

Value-gradient：动作值函数对策略动作的梯度  直接回传到策略参数，让学习信号直接优化策略。

离线 RL（χ⁰、RECAP）：学习完全在训练阶段完成，部署时策略固定。异步执行只是推理调度选择，不影响学习信号。优势通过加权（AWR）或条件化（CFG 引导）影响策略，而不是通过值梯度回传。

同步在线 RL（RLT、EXPO-FT、RL、LWD 等）：在真实机器人闭环中做 actor-critic 更新，值梯度直接回传。但都假设同步执行，部分分块执行从未进入公式。

异步受限在线 RL（GRRL）：在异步执行下做在线学习，但 RL 优化变量放在冻结扩散策略的隐空间噪声中，通过值函数选择候选而不是直接回传值梯度到原始动作空间。这限制了可达到的改进上限——因为冻结解码器确保每个输出动作都在预训练先验的动作分布内。

3.2 核心矛盾：梯度污染
在异步执行下，每个生成的动作分块只有一部分被执行，其余被下一个推理周期的分块覆盖。如果值梯度  回传到整个分块，策略更新会依赖于那些从未进入环境的动作——这就是梯度污染。
与前三类不同，异步在线 RL 无法通过设计来避免这个问题：只要走值梯度路径且异步部署，策略参数更新就必然暴露于未执行的、被覆盖的动作。因此，目标函数本身必须消除这种污染，而不是依赖执行调度。
SmoothRL 的解决思路有两个支柱：
显式区域划分 + 梯度截断：将分块按执行状态分为三个区域，只对执行区域回传梯度。

训练时就跑异步循环：回放缓冲区记录的是机器人在异步调度下真正执行的动作，而不是同步假设下的"理想"动作。

4. 方法深挖
我们从异步推理循环的时间线开始，逐步建立到目标函数和梯度截断的完整推导。
4.1 异步推理循环与区域划分
固定延迟预算  的引入
在真实部署中，推理延迟是波动的。每个分块的 committed 区域长度  由本次推理的延迟决定，execution 区域长度  由下一次推理的到达时间决定。这两个长度由不同的推理周期决定，独立波动，在生成分块时是未知的。
SmoothRL 没有建模这种随机性，而是通过固定延迟预算来消除它。具体做法是：估计推理时间的上界 ，强制执行一个调度循环——每个分块在其第一帧到期前  个控制步请求推理。如果推理提前完成，系统等待，确保分块交接总是在预定义的时间点发生。
这样，，两个区域长度都由同一个常数固定。对于任意  的分块：
Committed 区域：本次推理延迟期间经过的帧。这些帧的动作已经由前一个分块提供，当前分块在这个区域的预测永远不会影响环境。

Execution 区域：当前分块作为最新可用策略输出的时间段。这个区域的每个动作都会按生成的原样发给机器人，是分块中唯一直接决定环境轨迹的部分。

Discarded 区域：下一个分块到达后被覆盖的帧，永远不会到达环境。

为什么固定  而不是建模随机延迟？
建模随机延迟需要知道延迟的分布，并在目标函数中对其取期望。这会引入几个问题：(1) 延迟分布可能非平稳，受模型负载、系统调度影响；(2) 区域边界随机化后，梯度截断的位置也随机化，训练信号的方差增大；(3) 实现复杂度显著上升。固定预算是一个务实的工程选择，但代价是：如果实际推理时间偶尔超过预算，调度交接无法保证，异步循环会失稳。论文在 Limitations 中明确承认了这一点。

这是 SmoothRL 最精妙的设计之一，需要仔细理解。
Critic 看完整动作（committed + execution）有两个原因：
Chunk-skip bootstrap 无偏性：critic 必须以生成区间奖励的真实动作序列为条件。在异步执行下， 的动作是前一个分块发出的 ， 的动作是当前策略输出的 。如果 critic 只看 ，它就忽略了前  帧对奖励的贡献，TD backup 会有偏。

并发决策的状态增广：异步执行本质上是一个并发决策问题（concurrent decision process）。execution 区域不是从  开始行动，而是从  开始，中间的帧由正在飞行的分块控制。一个只以  为条件的 critic 会对回放缓冲区中未知的"在飞行分块"分布取边际化，而在离策略设置下，这反映的是旧策略的行为。因此需要用"正在飞行的动作"和"剩余时间"来增广状态。延迟预算将后者固定为常数 ，而 chunk-stitching 一致性使前者在生成时直接可用——每个新分块的 committed 区域恰好对应前一个分块已经发出的动作。

Actor 只对 execution 区域求梯度：从策略的角度看，committed 区域不产生有效的环境反馈——这些动作被前一个分块覆盖，不构成当前策略的有效梯度路径。因此值梯度被截断到 execution 区域： 只对  计算。
这个截断建立了一个关键的恒等式：接收值梯度的段同时是策略输出和环境实际执行的动作，使得梯度关于策略参数是良定义的。注意，截断只适用于梯度路径，critic 继续在完整动作分块上操作。
平滑性如何进入目标
可执行集合约束  限制的不是策略可以作用的帧，而是优化所遍历的分块集合。Actor 也以 committed 区域为条件，但原因与 critic 不同：因为 committed 和 execution 区域在帧索引  处相连，候选分块的选择必须意识到它需要延续的轨迹。
预训练策略的平滑性由 demonstrations 提供，而非显式强制执行。但是，一旦值目标在 execution 区域上增大 ，这种平滑性就不再有保证——策略可能为了追求高  值而产生剧烈的动作变化。因此，连续性必须作为显式约束重新引入目标函数。

Agreement 与 Differentiability 的讨论
论文提出了两个关键要求：
Agreement： 评估的动作必须恰好是机器人执行的动作。

Differentiability： 评估的动作必须有一条有效的梯度路径回到 。

直接执行策略输出天然满足这两个要求——这是公式 (4) 假设的设置。但第 2.4 节讨论的两类边界平滑方法在这里分道扬镳：
一致性约束在执行前修改分块，确保策略输出等于执行动作，agreement 保持。

轨迹混合在新旧分块都可用后才决定执行动作。为了保持 agreement，critic 必须评估混合后的实际执行动作。截断原则可以自然扩展：值梯度应该对每个贡献到执行窗口的分块计算，限制在该分块贡献的段上。因为这些段在不同 transition 间不重叠，每个分块恰好被微分一次。

但这个扩展需要目标跨度超过 、每个贡献分块额外的一次 actor 前向传播、以及围绕混合算子的连续性约束重构。论文为了简洁性，采用直接策略输出执行，通过约束优化来强制平滑性。这是一个合理的简化，但也留下了未来工作的空间。
4.4 人类干预的自然兼容
在真实机器人上做在线 RL，探索是昂贵的：失败的试验消耗时间，接触丰富的任务还可能造成硬件磨损。因此，人类干预已经成为真实机器人 RL 的标准组件，而不仅仅是便利。
SmoothRL 在原始动作空间操作，这使得人类干预可以自然融入，无需额外转换。论文支持两种干预模式：
绝对干预（Absolute Intervention）：遥操作的分块直接发出，actor 输出被丢弃。使用 VR 遥操作，操作员的手部姿态直接指定目标动作。适合需要高度灵活性和高精度的任务，演示动作可能与策略提出的轨迹有显著差异。
残差干预（Residual Intervention）：人类输入加到 actor 输出上，操作员修改策略生成的分块而不是替换它。使用手柄，摇杆位移指定动作增量。适合动态任务，因为它保留了底层动作分块的时间结构，操作员只需补偿偏差而无需控制整个速度曲线。
一个有趣的实验发现：在动态抛掷任务中，对于最远的容器位置（需要最高释放速度），VR 绝对遥操作的成功率约 30%，而残差干预约 80%。原因是绝对遥操作要求操作员同时控制释放速度的方向和大小，并在人机控制切换时保持连续性；残差干预保留了 base policy 的速度曲线，操作员只需补偿偏差，大幅降低了控制负担。
两种模式在下游被完全相同地处理：实际发出的动作记录在  中，用作 BC 目标。分块在分块级别被标记为已干预，这个标记决定 execution 区域的 BC 目标：已干预分块用实际发出的动作，否则用 base policy 参考动作。 的输入与干预标记无关——因为 committed 区域记录的是实际发出的动作，当前一个分块被干预时，它自然包含人类动作。

6. 实验复盘与结果分析
6.1 平台与任务
所有实验在 Astribot S1 上进行——一个 25 自由度的移动双臂机器人，包括两个 7-DoF 手臂（带平行夹爪）、4-DoF 躯干、2-DoF 头部和 3-DoF 轮式底座。
Base policy 的观测包括三路摄像头（头部、左手腕、右手腕），每路 224×224 分辨率，加上机器人本体感受关节状态。Base policy 以 30 Hz 输出 31 维动作（左右臂和躯干末端执行器各 9 维笛卡尔 delta 位姿 + 2 个夹爪命令 + 2 个头部关节命令）。附加 actor-critic 只修改 20 个手臂动作维度，躯干和头部动作不变。
推理请求频率为 5 Hz，即每 200 ms 到达一个新动作分块，对应延迟预算 

帧（30 Hz 下）。每个分块的 execution 区域贡献 6 帧，同时下一个分块在推理。Base policy 训练预测 
 帧/分块，因此 committed + execution 占 12 帧，剩余 20 帧为 discarded 区域。

三个任务覆盖了两种互补的场景：
动态抛掷（Dynamic Tossing）：抓起随机放置的物体，抛入随机放置的容器。容器开口约 7×12 cm，物体约 6×7 cm。成功需要末端执行器在挥臂过程中持续积累速度，而不是在单个瞬间达到目标速度。这使得任务对异步执行特别敏感：分块边界的停顿会让手臂几乎静止，剩余挥臂无法恢复所需释放速度。18 个评估配置（3 个物体位置 × 6 个容器位置）。
笔帽装配（Pen Capping）：将笔与笔帽对齐，将笔帽套到笔上，然后松开笔帽。成功插入需要笔和笔帽的相对位姿在约 5 mm 间隙容差内。双臂都主动控制，插入精度取决于相对位姿而非单臂运动。12 个评估配置（4 个初始手部状态 × 3 个笔帽位置）。
开箱（Box Opening）：左手稳定纸箱，右手将刀片插入盒盖接缝，沿接缝划开胶带，然后打开盒盖。刀片约 1 mm 宽，接缝仅 2–3 mm 宽，需要毫米级精度定位接缝。插入误差可能双向失败：刀片切入纸板损坏盒子，或错过胶带导致盒子保持密封。10 个评估配置。
6.2 训练设置
Base policy：₀.₅，针对每个任务微调，开箱和笔帽装配用 1500 条遥操作演示，动态抛掷用 500 条（抛掷遥操作本身只有约 50% 成功率，难以收集）。

在线 RL 从对应预训练策略开始，先收集 50 个 base policy rollout 播种缓冲区，然后引入附加网络。

评估点：0（base policy）、150、200、250 episode。

稀疏奖励：操作员通过手柄或 VR 接口判定 episode 成功/失败，无中间奖励。

干预策略：动态抛掷用残差干预（原因见 4.4 节），高精度任务用绝对干预。

6.3 成功率曲线与表格解读
三个任务在 250 episode 后都大幅超越冻结 base policy：
动态抛掷：39% → 94%（+55 个百分点）

笔帽装配：8% → 83%（+75 个百分点）

开箱：30% → 90%（+60 个百分点）

学习动态因任务而异：
动态抛掷和笔帽装配单调提升，最大增益在前 150 episode。笔帽装配尤其显著：8% → 67%，说明主导性的系统偏移在早期就被大幅修正，之后性能主要受修正轨迹周围残余变化的限制。

开箱呈现不同轨迹：150 episode 时降到 20%（低于 base policy），然后恢复到 40%，最终达到 90%。这种瞬态退化可能反映了附加网络在发现有效修正时所需的探索。

6.4 失败模式分析
Base policy 的失败是系统性的而非随机的：
笔帽装配：策略在不同笔帽位置产生相似的运动轨迹，未能充分调整，导致只有 8% 成功率。

开箱：刀片表现出一致的左偏，导致刺入纸板而非进入胶带接缝。

动态抛掷：策略未能根据目标距离适当调节释放速度——近处容器过冲，远处欠冲，同时对左右侧目标表现出系统性左右偏差。

在线 RL 逐步修正了这些系统性偏移。最终检查点的失败是"近似失误"（near misses）：
动态抛掷：物体落在离容器更近的位置，打破了 base policy 的固定偏差模式。

开箱：刀片偏离接缝的距离小得多，左右偏差在正确位置周围 1–2 mm。

笔帽装配：笔帽和笔管的轴向不对准也小得多，是正确位姿周围的小散布。

这些偏差量级正是任务的挑战性所在：成功不是关于到达目标区域，而是关于闭合最后几毫米。小到在图像中几乎无法区分的误差就足以导致 episode 失败。
6.5 平滑性量化
论文 Figure 1 的底部展示了平滑性结果：在真实自主抛掷 rollout 中，SmoothRL 相比 base policy 将加速度和 jerk 的 RMS 分别降低了 52% 和 47%。速度曲线更平滑，没有 base policy 在分块边界处的尖峰。
6.6 客观插评
提升幅度确实显著，三个任务都从"基本不可用"提升到"高度可靠"。但需要注意几个方法论限制：
单次 run：每个任务的三个非零检查点来自同一次 RL 运行，没有多次随机种子的方差报告。250 episode 后的成功率是单次运行的结果，不是均值加减标准差。

配置数量有限：每个任务 10–18 个评估配置，每个配置只评估一次。在这种样本量下，成功率的置信区间较宽。例如 18 次中成功 17 次（94%），95% 置信区间约为 73%–99%（Wilson 区间近似）。

主要对比基座策略：唯一的对比是冻结 base policy。缺少与强异步 baseline 的对比——比如在异步部署下直接应用同步在线 RL（不做梯度截断）的效果，或者与 GRRL（隐空间异步 RL）的头对头比较。

缺少系统消融：没有消融梯度截断的贡献（如果不截断会怎样？）、平滑正则的贡献、固定延迟预算的影响等。

稀疏奖励 + 人工判定：成功由操作员人工判定，虽然减少了奖励工程的负担，但引入了判定者主观性，且复现需要相同的判定标准。

这些限制不否定结果的价值，但意味着我们应该将其视为"有前景的概念验证"而非"定论性的证据"。
7. 相关工作对照与定位
7.1 与轨迹混合、前缀约束的关系
如第 2.4 节所述，前缀约束和轨迹混合是两类主要的异步部署平滑手段。它们对模仿学习和离线 RL 区别不大，但对在线 RL 是决定性的。SmoothRL 选择了直接执行策略输出（不使用外部混合算子），通过约束优化来强制平滑性。这避免了混合算子带来的 agreement/differentiability 复杂性，但也意味着平滑性完全依赖于策略内部的学习和正则项，而非后处理保证。
7.2 与隐空间异步 RL（GRRL）的对比
GRRL 是最接近的对比工作。它在异步执行下做在线学习，但将 RL 优化变量放在冻结扩散策略的隐空间噪声中。关键区别：

GRRL 的冻结解码器确保每个输出动作都在预训练先验的分布内，这既限制了误差也限制了改进。SmoothRL 在原始动作空间操作，理论上可以表达超出 base policy 分布的修正（尽管当前实例化用了有界残差）。
7.3 与同步值梯度方法的对比
RLT、EXPO-FT、RL、LWD 等同步在线 RL 方法都假设整个分块被执行，值梯度可以回传到分块的每一帧。SmoothRL 的核心增量是将异步执行显式建模为优化约束——区域划分 + 梯度截断。因为公式操作在原始动作分块上而非特定策略参数化，它同样适用于残差策略适应和端到端策略微调。
7.4 论文的差异点
据我们所知，在现有公开工作中，较少见到将异步执行的时序结构完整显式嵌入值梯度目标的形式化。SmoothRL 的贡献可以概括为三个要素的组合：
直接在原始动作空间做值梯度（而非隐空间选择）。

显式区域截断（committed / execution / discarded）。

训练-部署一致（训练时就跑异步循环）。

8. 结语
异步执行不是部署细节，而是优化目标必须显式建模的约束。当推理与执行重叠时，"策略生成的动作"和"机器人执行的动作"不再是同一个东西——如果值梯度回传到那些从未进入环境的动作上，策略优化就会偏离实际执行轨迹。
SmoothRL 给出了一个清晰、可实现的答案：将每个动作分块划分为 committed、execution、discarded 三个区域，只对真正被执行的区域回传值梯度，同时在训练时就运行异步循环，确保回放缓冲区记录的是真实执行的动作。这个形式化干净利落，工程实现务实（残差 + 人类干预 + 真实机器人），在三个高难度任务上取得了显著的成功率提升和平滑性改善。
但 SmoothRL 也暴露了当前真实机器人在线 RL 的共同挑战：数据效率（250 episode 对小网络可行，对大模型不够）、干预依赖（人类操作员在训练中扮演关键角色）、统计严谨性（单次 run、弱 baseline、缺消融）。这些是整个领域的问题，不是 SmoothRL 独有的。
对于研究者，SmoothRL 打开了"异步 + 在线值梯度"这个交叉点，后续可以在可变延迟建模、端到端微调、混合算子纳入目标等方向继续探索。对于工程实践者，它提供了一个可以直接参考的部署框架——如果你在异步管线上做在线 RL，梯度截断是一个必须考虑的问题。
