### 想法 1：错演示不是一类错：动作、对象、时序三轴反事实诊断
- 一句话总结：把“错误演示”拆成动作正确对象错、对象正确时序错、任务正确物理条件错三类，测 one-shot 策略到底读了哪一层上下文。
- 贡献类型：诊断
- 目标具身：单臂桌面操作臂，平行夹爪，RGB + 本体感知，动作块控制。
- 目标基准 / 仿真器 / 数据集 / 开放权重：StellaVLA 开放评测权重 + LIBERO / LIBERO-Plus；可加 RICL-π0-FAST checkpoint 在 DROID 风格任务上做复核。
- 所针对的核心瓶颈（对应框架文件中的缺口编号）：缺口 4、缺口 6。
- 与 insights/11 中最接近一条的区别：最接近第 4 条“三种上下文接口同台对照”和第 20 条“视频演示注入”；区别是这里不比较接口，也不先做安全攻击，而是把演示错误做成可控反事实因子，定位模型利用上下文的具体捷径。
- 最小 sim-first pilot（可在 ≤ 8 卡 × 1 周内完成）：在 LIBERO-Plus 选 12 个未见/扰动任务，每个任务构造 1 条正确演示、3 条反事实演示和 1 条随机演示；直接跑 StellaVLA 评测脚本，每格 100 rollout，不训练新模型，只重排或自动生成结构化演示输入。
- 必报指标（成功 + 失败）：二元成功率；相对正确演示的成功率跌幅；三类反事实下动作偏移距离、目标物误选率、阶段顺序错误率；每任务 rollout 数、扰动档位、是否允许重试和干预次数均单列声明。
- 若想法不成立，最可能的失败模式：StellaVLA 在 LIBERO 上主要读任务标签而非演示细节，三类反事实造成的输出差异过小。
- 是否真正需要真机：否
- 负结果是否仍可发表，为什么：可以；若三类错演示差异不显著，说明现有 LIBERO 式 one-shot 分数不能证明模型读懂演示，是对饱和基准的可复现负面证据。
- 命名的最大风险：标签捷径塌缩风险。

### 想法 2：异步动作块里的上下文污染：输出历史 vs 执行历史审计
- 一句话总结：在仿真中显式模拟动作块被覆盖的异步部署，比较把“策略输出”或“环境实际执行”写入上下文时自我改进是否发生偏差。
- 贡献类型：诊断
- 目标具身：单臂桌面操作臂，关节动作块或末端动作块，带跨尝试记忆。
- 目标基准 / 仿真器 / 数据集 / 开放权重：Zeva 开放代码与 zeva-robocasa 权重 + RoboCasa365-Atomic5；可附 ICRT-MT 离线日志做纯日志版 sanity check。
- 所针对的核心瓶颈（对应框架文件中的缺口编号）：缺口 5、缺口 6。
- 与 insights/11 中最接近一条的区别：最接近第 13 条；区别是第 13 条只提出切换上下文来源，这里进一步加入固定延迟、覆盖窗口和 discarded 段比例三档，让错误来源可归因到异步部署机制。
- 最小 sim-first pilot（可在 ≤ 8 卡 × 1 周内完成）：在 RoboCasa365-Atomic5 复现 Zeva CSR@K，加入一个不改策略的异步执行 wrapper；对每个 episode 记录 proposed chunk、committed 段、execution 段和 discarded 段，分别喂给 Zeva 记忆模块，跑 K=1..4 的累计成功曲线。
- 必报指标（成功 + 失败）：CSR@1/2/3/4；同一 episode 的无记忆重试曲线；输出历史与执行历史的动作差异；失败类型含碰撞、抓空、阶段回退、重复尝试；延迟预算、chunk 长度、重试次数、干预次数和二元/CSR 口径分开声明。
- 若想法不成立，最可能的失败模式：Zeva 的记忆主要依赖最终观测而非动作历史，输出/执行来源切换不会改变 CSR 曲线。
- 是否真正需要真机：否
- 负结果是否仍可发表，为什么：可以；若两种历史等价，能收窄 RoboTTT/Zeva 类方法的风险边界，并为异步部署论文提供一个反直觉对照。
- 命名的最大风险：记忆旁路风险。

### 想法 3：演示最小充分帧：从整段视频 ICL 改成证据子序列 ICL
- 一句话总结：用进度对齐和失败敏感遮挡找出演示中真正必要的帧段，只把最小充分子序列送入上下文。
- 贡献类型：方法
- 目标具身：单臂或双臂桌面操作臂，RGB 演示视频条件，动作块策略。
- 目标基准 / 仿真器 / 数据集 / 开放权重：HOST 代码/权重用于进度对齐模块离线分析；Fast-WAM 或 StellaVLA + LIBERO / RoboTwin 2.0 做仿真闭环；ATM 开放权重提供点轨迹辅助标注。
- 所针对的核心瓶颈（对应框架文件中的缺口编号）：缺口 3、缺口 4、缺口 10。
- 与 insights/11 中最接近一条的区别：最接近第 8 条“潜动作当演示编码”和第 22 条“上下文容量边界”；区别是这里不换成潜动作表示，也不只画长度曲线，而是提出可执行的帧选择策略并报告哪些帧被证明不可省。
- 最小 sim-first pilot（可在 ≤ 8 卡 × 1 周内完成）：在 LIBERO-Plus 选 10 个任务，先用 SDTW/视觉嵌入对齐演示与执行，再做帧段遮挡，训练一个小型帧段打分器或直接贪心选择 20%/40%/60% 帧；用冻结 Fast-WAM/StellaVLA 评测完整演示、均匀采样、最小充分帧三组。
- 必报指标（成功 + 失败）：二元成功率；上下文 token/帧数；推理延迟；对齐误差；失败模式按漏掉接触前帧、漏掉目标确认帧、漏掉释放阶段、误选无关帧统计；声明是否任务级未见和每格 rollout 数。
- 若想法不成立，最可能的失败模式：模型对演示帧顺序和密度高度敏感，删帧带来的分布偏移大于去噪收益。
- 是否真正需要真机：后续验证可选
- 负结果是否仍可发表，为什么：可以；若无法压缩，说明“长上下文不是冗余而是承载动作阶段证据”，直接约束后续 ICL 系统设计。
- 命名的最大风险：删帧分布偏移风险。

### 想法 4：同一演示，不同物理：视觉 one-shot 的不可辨识性基准
- 一句话总结：构造视觉上几乎相同但质量、摩擦、铰链阻尼不同的任务族，检验纯视觉演示 ICL 在接触密集任务上的理论边界。
- 贡献类型：评测协议
- 目标具身：单臂桌面操作臂，平行夹爪，无触觉/力传感，RGB-D 可用于仿真日志但策略输入默认 RGB。
- 目标基准 / 仿真器 / 数据集 / 开放权重：RLBench 或 RoboTwin 2.0 仿真；任务包括开抽屉、推按钮、插装、拧旋钮；对照模型为 OpenVLA-OFT、SmolVLA、Fast-WAM 或 ICRT 权重中可接入仿真的开放项。
- 所针对的核心瓶颈（对应框架文件中的缺口编号）：缺口 9、缺口 6。
- 与 insights/11 中最接近一条的区别：最接近第 18 条“NEXT 进 one-shot 演示管线”；区别是这里先不引入力传感或 NEXT，而是用仿真隐藏物理参数证明仅靠视频演示哪些任务不可辨识。
- 最小 sim-first pilot（可在 ≤ 8 卡 × 1 周内完成）：在 RLBench 改 4 个任务的质量、摩擦、阻尼参数，每个参数 3 档，渲染同视角演示视频，保证首尾视觉状态相同；用冻结策略或轻量行为克隆基线测试 one-shot 条件下的跨参数泛化。
- 必报指标（成功 + 失败）：二元成功率；接触建立失败率、过力/欠力代理事件、滑移率、卡滞率、动作重复次数；参数档位、是否给物理标签、是否使用 RGB-D、试验数和重试/干预口径全部单列。
- 若想法不成立，最可能的失败模式：现有仿真任务的物理差异不足以改变可见运动，模型失败主要来自感知/控制而非隐藏力学。
- 是否真正需要真机：否
- 负结果是否仍可发表，为什么：可以；若隐藏物理不影响表现，说明接触任务的主要瓶颈不在力信息，而在别的环节，可纠正本领域对“纯视觉必然缺力”的笼统说法。
- 命名的最大风险：仿真物理伪难度风险。

### 想法 5：演示可信度不是安全问题才需要：上下文一致性裁决器
- 一句话总结：把“有演示、无演示、随机演示、反事实演示”四路输出分歧变成部署前的演示可信度分数，过滤普通错误演示和恶意演示。
- 贡献类型：方法
- 目标具身：单臂桌面操作臂，RGB 观测，冻结 one-shot 策略外接裁决器。
- 目标基准 / 仿真器 / 数据集 / 开放权重：StellaVLA + LIBERO-Plus；RoboMonkey monkey-verifier-7b 作为动作验证器初始化；可加 HOST 开放权重做离线动作分歧分析。
- 所针对的核心瓶颈（对应框架文件中的缺口编号）：缺口 4、缺口 8。
- 与 insights/11 中最接近一条的区别：最接近第 20 条和第 21 条；区别是这里不把问题限定为攻击/防御，而是把正常部署中的错拍、漏拍、任务相似演示一起纳入可信度校准，目标是“何时不该相信演示”。
- 最小 sim-first pilot（可在 ≤ 8 卡 × 1 周内完成）：在 LIBERO-Plus 生成 500 组正确/随机/近邻错误/目标冲突演示；冻结 StellaVLA 产生候选动作，RoboMonkey 验证器或轻量二分类头只读当前观测和候选动作，预测是否采纳演示条件输出。
- 必报指标（成功 + 失败）：过滤前后成功率；坏演示检出率、正常演示误拦率；动作分歧 AUC；被拒后回退策略成功率；失败模式含过度保守、误拒新任务、未检出目标冲突；声明演示类型、rollout 数、是否零更新和干预次数。
- 若想法不成立，最可能的失败模式：动作验证器没有接触目标或阶段信息，无法区分合理的新演示和危险/错误演示。
- 是否真正需要真机：后续验证可选
- 负结果是否仍可发表，为什么：可以；若分歧无法可靠区分可信度，说明 StellaVLA 式三向干预不能直接转成部署安全机制，避免社区过度解读。
- 命名的最大风险：分歧误校准风险。

### 想法 6：one-shot 不是一个数字：成本归一化适应前沿
- 一句话总结：用统一成本轴比较 ICL、检索、测试时验证、重试记忆和少步微调，报告每多花一分钟或一次尝试真正买到多少可靠性。
- 贡献类型：评测协议
- 目标具身：单臂桌面操作臂，桌面短程与中长程任务，RGB 条件。
- 目标基准 / 仿真器 / 数据集 / 开放权重：LIBERO-Plus、RoboCasa365-Atomic5、RLBench-Oneshot；开放系统包括 StellaVLA、Zeva、RICL、RoboMonkey、OpenVLA-OFT/SmolVLA。
- 所针对的核心瓶颈（对应框架文件中的缺口编号）：缺口 3、缺口 6。
- 与 insights/11 中最接近一条的区别：最接近第 11、12、19 条；区别是这里不提出三段流水线或真机协议，而是定义一个 sim-first、成本归一化的横向前沿图，统一“上下文、采样、重试、梯度步”的预算口径。
- 最小 sim-first pilot（可在 ≤ 8 卡 × 1 周内完成）：选 LIBERO-Plus 10 任务和 RoboCasa365 5 任务，给每个方法固定 0 秒、30 秒、2 分钟、10 分钟测试时预算；跑无上下文、one-shot 上下文、RoboMonkey 采样验证、Zeva 式 K 次重试、少步 LoRA 微调五类公开实现或轻量复现。
- 必报指标（成功 + 失败）：同一二元口径下的成功率-成本曲线；GPU 秒、wall-clock、环境尝试次数、上下文长度、梯度步数；失败模式、干预次数、重置次数和是否评测期更新分列；严禁和 CSR/progress 直接混排。
- 若想法不成立，最可能的失败模式：不同开放模型绑定不同动作空间和任务分布，横向比较仍残留不可控变量。
- 是否真正需要真机：否
- 负结果是否仍可发表，为什么：可以；即使只证明无法公平横比，也能给 CoRL/RSS 社区一个明确的披露清单，减少跨口径比大小。
- 命名的最大风险：动作空间不可比风险。

### 想法 7：从失败中读约束：失败 rollout 作为负上下文
- 一句话总结：不让模型只看成功演示，而是在上下文里加入一次失败执行及其失败标签，测试它能否学会“不要这样做”。
- 贡献类型：方法
- 目标具身：单臂桌面操作臂，短程抓放/开合/插装任务，RGB + 本体感知。
- 目标基准 / 仿真器 / 数据集 / 开放权重：ICRT 代码/权重 + ICRT-MT；LIBERO 或 RLBench 生成失败 rollout；RICL-π0-FAST 作为后装 ICL 对照。
- 所针对的核心瓶颈（对应框架文件中的缺口编号）：缺口 3、缺口 4、缺口 5。
- 与 insights/11 中最接近一条的区别：最接近第 12 条“自我改进公平基线”和第 13 条“执行历史来源”；区别是这里不研究多次重试后的记忆曲线，而是研究单个失败片段作为显式负例能否改变下一次 one-shot 决策。
- 最小 sim-first pilot（可在 ≤ 8 卡 × 1 周内完成）：在 LIBERO 选 8 个任务，自动收集抓空、放错、碰撞、阶段错序四类失败 rollout；构造“成功演示 only”“失败 only”“失败 + 成功”“成功 + 失败标签”四种上下文，用冻结或小规模微调的 ICRT/RICL 跑每格 50-100 rollout。
- 必报指标（成功 + 失败）：二元成功率；同类失败复发率；失败类别迁移矩阵；上下文顺序敏感性；是否允许重试、是否使用人工失败标签、每任务试验数和干预次数。
- 若想法不成立，最可能的失败模式：现有 ICL 接口把失败轨迹当成可模仿演示，负例反而诱导重复错误。
- 是否真正需要真机：否
- 负结果是否仍可发表，为什么：可以；若负上下文系统性伤害策略，说明“把历史塞进上下文”并不自动等于学习，直接约束 Zeva/RoboTTT 式叙事。
- 命名的最大风险：负例模仿风险。

### 想法 8：未见到底未见什么：任务、物体、布局、具身四轴泄漏审计
- 一句话总结：把 one-shot 评测中的“未见”拆成四个可独立控制的轴，检测开放权重是否在训练或评测协议中泄漏了任务信息。
- 贡献类型：诊断
- 目标具身：单臂桌面操作臂为主，可加入 RoboTwin 2.0 的多机械臂设定做具身轴。
- 目标基准 / 仿真器 / 数据集 / 开放权重：RoboTwin 2.0、LIBERO-Plus、OpenVLA-OFT、SmolVLA、Fast-WAM、LingBot-VA v1；不使用 LingBot-VA 2.0 闭源主张作主实验。
- 所针对的核心瓶颈（对应框架文件中的缺口编号）：缺口 1、缺口 6、缺口 7。

- 最小 sim-first pilot（可在 ≤ 8 卡 × 1 周内完成）：在 RoboTwin 2.0 和 LIBERO-Plus 各选 10 个任务，构造只换物体、只换布局、只换任务组合、只换机器人描述/动作头四组；对开放 checkpoint 做零更新评测，并用 README/训练集声明给每个任务打泄漏风险标签。
- 必报指标（成功 + 失败）：四轴分层成功率；训练集相似度分数；失败模式含目标语义错、抓取几何错、动作空间错、阶段规划错；每个模型的训练数据可见性声明、rollout 数、干预/重试/更新状态。
- 若想法不成立，最可能的失败模式：训练数据披露不足，泄漏标签只能半自动推断，无法形成强结论。
- 是否真正需要真机：否
- 负结果是否仍可发表，为什么：可以；若无法判定未见轴，本身就是对开放权重论文披露不足的量化证据。
- 命名的最大风险：披露黑箱风险。

### 想法 9：小而硬的人类视频-仿真轨迹配对集：只采高信息阶段

- 目标基准 / 仿真器 / 数据集 / 开放权重：RoboTwin 2.0 或 RLBench；ATM/Im2Flow2Act 生成点轨迹与光流标签；下游评测用 ICRT、Fast-WAM 或 StellaVLA 可接接口。
- 所针对的核心瓶颈（对应框架文件中的缺口编号）：缺口 10、缺口 4、缺口 9。
- 与 insights/11 中最接近一条的区别：最接近第 16 条“真实演示测试”和第 17 条“自动标注与质检”；区别是这里产出新的小规模配对数据，并故意覆盖接触前、接触中、失败恢复等高信息阶段，而不是只测试野生视频或审计自动标注质量。
- 最小 sim-first pilot（可在 ≤ 8 卡 × 1 周内完成）：用 RLBench/RoboTwin 脚本生成 20 个任务的机器人成功/失败轨迹；人工用手机拍同任务的第三人称演示 300 条，手工标 5 个阶段和接触事件，先发布 10 任务 mini split，并跑帧检索/阶段对齐 baseline。
- 必报指标（成功 + 失败）：配对覆盖率；阶段标注一致性；接触事件标注一致性；检索 top-k 阶段命中率；下游 one-shot 成功率只作为次要指标；同时报告失败轨迹比例、标注拒收率和数据许可口径。
- 若想法不成立，最可能的失败模式：少量配对数据不足以训练策略，只能用于诊断，审稿人可能质疑数据贡献规模。
- 是否真正需要真机：否
- 负结果是否仍可发表，为什么：可以；即使不提升策略，小而高质的配对诊断集仍补齐公开配对数据稀缺，可复现地服务后续方法消融。
- 命名的最大风险：规模轻视风险。

### 想法 10：HOST-in-Sim 复现舱：先复现接口，不复现 50 个真机任务
- 一句话总结：为 HOST 开放权重做一个最小 ARX R5 仿真适配舱，验证它的相机、动作维度、进度对齐和技能检索接口能否被第三方独立跑通。
- 贡献类型：数据
- 目标具身：双臂 ARX R5，3 路 RGB，20 维末端动作块，桌面短程双臂任务。
- 目标基准 / 仿真器 / 数据集 / 开放权重：HOST 官方代码 + Guangyan/HOST 权重；RoboTwin 2.0 或 Isaac/ManiSkill 中自建 ARX R5 近似模型；从 HOST 50 任务中抽象 5-8 个可仿真的抓放/开合/擦拭任务。
- 所针对的核心瓶颈（对应框架文件中的缺口编号）：缺口 1、缺口 6、缺口 10。
- 与 insights/11 中最接近一条的区别：最接近第 19 条“标准协议”；区别是这里不试图一次性建立社区真机协议，而是先交付一个开放权重可执行的仿真复现舱，目标是让第三方能跑 HOST 的接口链路和失败日志。
- 最小 sim-first pilot（可在 ≤ 8 卡 × 1 周内完成）：用现成 URDF/近似双臂模型搭 5 个桌面任务，重建 HOST 需要的 3 相机输入和动作解码 wrapper；先跑离线演示-执行进度对齐，再跑闭环 rollout，失败也保留轨迹与渲染视频。
- 必报指标（成功 + 失败）：接口跑通率；进度对齐误差；二元成功率仅作为复现舱内部数字，不与 HOST 真机 62% 横比；失败模式含动作尺度错、相机外参错、双臂碰撞、进度错配；声明仿真与真机不可比、每任务 rollout 数、重试/干预状态。
- 若想法不成立，最可能的失败模式：HOST 权重过度绑定真实 ARX R5 标定和私有任务分布，仿真适配无法产生有意义动作。
- 是否真正需要真机：后续验证可选
- 负结果是否仍可发表，为什么：可以；若开放权重无法脱离私有硬件设定跑通，正是“开放但不可复现”的实证审计。
- 命名的最大风险：适配器失真风险。

### 想法 11：二元成功率掩盖的“准成功”：连续进度曲线重算具身 ICL
- 一句话总结：对同一批 rollout 同时报二元成功、阶段进度、可恢复失败和动作平滑性，检查 one-shot 改进是否只是把失败推迟到后段。
- 贡献类型：评测协议
- 目标具身：单臂桌面操作臂，短程和长程组合任务。
- 目标基准 / 仿真器 / 数据集 / 开放权重：RLBench-Oneshot、LIBERO-Plus、RoboCasa365；ManiLong-Shot 协议作为长程任务模板；开放模型用 Zeva、StellaVLA、OpenVLA-OFT/SmolVLA。
- 所针对的核心瓶颈（对应框架文件中的缺口编号）：缺口 6、缺口 2。
- 与 insights/11 中最接近一条的区别：最接近第 1 条“涌现之争裁决”和第 19 条“标准协议”；区别是这里不用产业规模检查点，也不做真机标准，而是在公开仿真中把一个 rollout 重算成多种指标，寻找二元阈值造成的假跃迁。
- 最小 sim-first pilot（可在 ≤ 8 卡 × 1 周内完成）：在 RLBench-Oneshot 20 个长程任务和 LIBERO-Plus 10 个扰动任务上保存所有 rollout；用任务阶段自动判定器或人工小样本校准，把每次执行转成二元、阶段进度、最后可恢复阶段、轨迹平滑和碰撞计数。
- 必报指标（成功 + 失败）：二元成功率；阶段 progress；失败发生阶段分布；可恢复失败率；碰撞/超时/抖动率；同一 rollout 的多口径表，明确哪些数字不可与 HOST/S1/Zeva 直接比较。
- 若想法不成立，最可能的失败模式：自动阶段判定噪声太大，导致连续指标比人工二元判定更不稳定。
- 是否真正需要真机：否
- 负结果是否仍可发表，为什么：可以；若多口径高度一致，说明二元成功率在这些公开基准上足够稳健，反而给社区一个简化评测的证据。
- 命名的最大风险：阶段标注噪声风险。

### 想法 12：后装 ICL 的代价账：新能力之外，旧能力掉在哪里
- 一句话总结：在同一开放基座上给 ICL 接口做小数据后装，系统测任务适应增益与原有 VLM/动作能力侵蚀之间的交换曲线。
- 贡献类型：诊断
- 目标具身：单臂桌面操作臂，RGB 输入，动作 token 或动作块输出。
- 目标基准 / 仿真器 / 数据集 / 开放权重：OpenVLA / OpenVLA-OFT、π0/openpi、RICL-π0-FAST、SmolVLA；LIBERO、LIBERO-Plus、DROID 子集、RefCOCO/具身 VQA 小集合作非动作能力 probes。
- 所针对的核心瓶颈（对应框架文件中的缺口编号）：缺口 7、缺口 3。
- 与 insights/11 中最接近一条的区别：最接近第 14 条；区别是第 14 条测多阶段训练后的存留率和换头稳定性，这里只关注“为了获得 ICL 接口而进行的后装训练”这一具体干预，并把增益-侵蚀画成同一条曲线。
- 最小 sim-first pilot（可在 ≤ 8 卡 × 1 周内完成）：以 openpi/π0 或 OpenVLA-OFT 为基座，用 ICRT-MT 或小规模 LIBERO 演示做 1k/5k/20k step 后装 ICL 微调；每个 checkpoint 同时跑 LIBERO-Plus one-shot、原始无上下文 LIBERO、DROID 检索任务和小型视觉接地 probe。
- 必报指标（成功 + 失败）：one-shot 成功率增益；原任务成功率保留率；视觉接地准确率保留率；动作头 KL/轨迹误差；失败模式含语言接地退化、动作抖动、只复制近邻、无上下文能力下降；声明训练步数、数据量、是否评测期零更新。
- 若想法不成立，最可能的失败模式：开放基座缺少可比的训练前后接口，视觉接地 probe 与机器人性能相关性弱。
- 是否真正需要真机：否
- 负结果是否仍可发表，为什么：可以；若后装 ICL 几乎没有侵蚀，能反驳“ICL 接口必然毁底座”的担忧，并给小组一条低成本方法路线。
- 命名的最大风险：probe 失配风险。

如果只能选一条，我选想法 4。同一演示、不同物理的不可辨识性基准最适合小组条件：全仿真、无需真机、无需复现 HOST/GEN 级预训练，却直击视频 ICL 的核心边界。它的负结果也有价值：若纯视觉仍稳健，力信息缺口被削弱；若系统性失败，就能把“接触密集任务为什么需要新信息通道”讲清楚。
