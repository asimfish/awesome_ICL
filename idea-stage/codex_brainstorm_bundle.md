# 想法生成任务包（ARIS /idea-creator · robotics framing）

你是一名资深机器人学习研究者（CoRL / RSS / ICRA 常任审稿人）。请先完整阅读以下三个文件，再开始生成：

1. `idea-stage/ROBOTICS_FRAME_AND_LANDSCAPE.md` —— 问题框架（Phase 0）与 24 项工作的机器人视角全景矩阵、10 条主要缺口（Phase 1）
2. `insights/11_open_problems_zh.md` —— 本仓库已整理的 22 条研究机会（各配最小可行实验）。**不要照抄这 22 条**；可以把它们当作出发点重组、拆分、反转或跳出去，但每条新想法必须说明它与最接近的那条清单项的区别
3. `insights/12_numbers_ledger_zh.md` —— 26 个头条数字的口径账本，用来避免提出「跨口径比大小」的想法

## 研究方向

在**无法复现 HOST / GEN 级预训练**（20 万条同具身真机轨迹 + 64 卡 × 60 万步）的约束下，具身 In-Context Learning / one-shot 技能习得领域，一个只有 ≤ 8×80GB GPU、单实验 ≤ 1 周、默认无真机（仿真优先；可选购置与 HOST 同款 ARX R5 双臂以直接使用其开放权重）的研究组，最值得做什么。

## 硬约束

- 目标会议：CoRL / RSS / ICRA / IROS / RA-L。
- **仿真优先**：每条想法必须有一个不依赖真机的最小 pilot（仿真 / 离线日志 / 对既有输出的分析）。真机只能是后续验证，且要标注是否「必需」。
- **基准具体化**：没有具体基准 / 仿真器 / 数据集 / 开放权重的想法直接不要写。可用资产见框架文件。
- **必须报告失败指标**：除成功率外要有失败模式、干预次数、口径声明等。
- **拒绝「基础模型戏剧」**：「把 X 模型用到机器人任务 Y」而没有新的瓶颈分析的想法不要写。
- **诊断类、评测类、负结果类贡献同样欢迎**，但要说明为何即使结果为负也值得发表。
- 不要为了规避风险堆模块；一个大胆想法 + 一条命名的风险，优于一个模块堆叠的稻草人。

## 输出要求

生成 **12 条**想法，覆盖至少四种贡献类型（方法 / 诊断 / 评测协议 / 数据）。**用简体中文**输出，每条严格按以下字段：

```
### 想法 N：<标题>
- 一句话总结：
- 贡献类型：方法 / 诊断 / 评测协议 / 数据
- 目标具身：
- 目标基准 / 仿真器 / 数据集 / 开放权重：
- 所针对的核心瓶颈（对应框架文件中的缺口编号）：
- 与 insights/11 中最接近一条的区别：
- 最小 sim-first pilot（可在 ≤ 8 卡 × 1 周内完成）：
- 必报指标（成功 + 失败）：
- 若想法不成立，最可能的失败模式：
- 是否真正需要真机：是（必需）/ 否 / 后续验证可选
- 负结果是否仍可发表，为什么：
- 命名的最大风险：
```

最后附一段 200 字以内的「如果只能选一条，你选哪条，为什么」。不要输出其他内容。
